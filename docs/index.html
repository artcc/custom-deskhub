01 / The idea

Configure once.
Change your mind anytime.

Your device keeps the same /display URL. Choose what that URL returns from the panel on your server.

  1. 01

    Run the backend

    Start the Node.js service or a Docker container on a machine reachable from your DeskHub’s private network.

  2. 02

    Choose your content

    Open the web panel, pick a source and preview your draft. Save when you want it to become the active output.

  3. 03

    Let DeskHub fetch it

    Use API mode with JSON key content. Set it in the device’s interface or from our Device tab. Saved content changes are available on the next poll.

Try a draft before saving

See your draft on a 32 × 7 grid of 224 LED cells, with bitmap letters, a column count and optional scroll playback. The full ASCII output stays readable below it. Preview never changes saved settings or sends content to the hardware.

Manage keys in your own panel

Add or remove provider keys through the web panel. Keys stay on your server, encrypted at rest with AES-256-GCM and a separate local key.

03 / Your workspace

A place for every setting.

Three tabs keep content, provider keys and hardware settings easy to find. Switching tabs preserves your unsaved fields, with visible pending-change indicators.

  1. 01

    Display

    Choose text, GitHub or weather, individually or in rotation. Edit each message, generate a draft preview and save the content served at /display.

  2. 02

    Integrations

    Save, replace or remove GitHub and OpenWeatherMap keys. Provider shortcuts help you get a key; saved keys are never shown again.

  3. 03

    Device

    Save the hardware’s local IP, check connectivity and apply one of its four built-in display modes, with the options for that mode.

Your message, with live values.

In Display, choose GitHub or weather and edit Message format. Variable buttons insert at the cursor; preview the result before saving.

A little motivation

GitHub message format 
Today I made {{commits}} commits. Keep going!

Available variables: {{commits}}, {{repositories}} and {{username}}.

The default is {{commits}}, producing just 7, for example. Add {{repositories}} for repository names and counts. All wording comes from your template.

A bit of outside context

Weather message format 
In {{city}}: {{temperature}} {{unit}} - {{condition}}

Available variables: {{city}}, {{temperature}}, {{unit}} and {{condition}}.

The default is {{temperature}} {{unit}}, producing 23 C, for example. Temperature is rounded, units are C or F, and the optional condition is OpenWeatherMap's description, such as clear sky.

Each source keeps its own format, up to 2048 characters. The backend adds no wording or summaries. Reset format restores the source's default in the draft. An empty format produces empty output. Unknown variables are rejected and final text is normalized to printable ASCII.

Older formats using only {{content}} load as the new defaults. Inside custom formats, this legacy variable inserts only the commit count or rounded temperature; your literal text is preserved.

The LED grid has 32 columns and 7 rows. Its proportional bitmap font matches the official “Hello” example and is clipped to seven rows, which can crop descenders and symbols. Text does not wrap or shrink to fit. Play, pause or scrub the scroll simulation to inspect longer messages. Font, alignment and timing remain a simulation rather than a pixel-for-pixel verified firmware replica; preview controls do not change the device’s scroll setting.

Message format reference ↗

One favourite, or a rotation.

Enable Rotate sources and select at least two sources. The order is Text → GitHub → Weather, with unchecked sources skipped. Each keeps its own message; use the source cards to edit and preview it.

Every source gets the same duration: the last fetch interval applied from Device, or 60 seconds by default. There are no separate timers to configure. Changes made directly in the hardware’s interface cannot be detected.

The device stays in API mode. Unavailable sources are skipped and reported in the panel; if none can render, the response is an error. Rotation follows the server clock, so extra requests do not advance it. The physical display changes on its next poll.

Runs on the device
  1. 01

    Save the IP

    Open Device, enter the DeskHub’s private IP without http://, then select Save IP. This only saves the address on your server.

  2. 02

    Check and configure

    Check connection reads the firmware form to check compatibility. Select a mode and fill in its options. In API mode, Use this panel helps fill the URL, key and interval.

  3. 03

    Apply to DeskHub

    Send the complete display configuration. This overwrites the device’s display settings, including retained values for inactive modes. Wi-Fi settings are separate and are never submitted.

Use API for custom content

Text, custom GitHub messages and weather from this panel all use the hardware’s API mode. Native GitHub and X modes use the firmware’s integrations, independently of the keys saved here.

Remembered settings, clearly labelled

The inspected firmware does not expose saved settings. This form starts with defaults or the last acknowledged submission from this panel, not a live reading. Changing the saved IP resets the remembered configuration.

Connect when you choose

Opening this panel does not contact the device. Checking the connection reads its form; applying sends the settings. Clear the saved IP to unlink. Content changes in Display remain available through normal polling.

An honest result

Acknowledgement means the device accepted the HTTP submission, not that its display or persistence was verified. If the response is lost, the result is unconfirmed and the submission is not retried automatically. Check the hardware before sending again.

05 / Make it yours

From repository to desk.

Clone or download the repository, then run these commands from its directory.

Native Node.js

Node 26 LTS · npm 11

Install the locked dependencies and start the server.

$ npm ci
$ npm start

Startup loads .env. Keep PORT and LOCALHOST configured; the supplied template uses port 3005.

Node.js instructions ↗

OrbStack

macOS development

With OrbStack installed, build and start the local container.

$ ./run_dev.sh

The helper uses .env-dev, persists data in ./data-dev and waits for a healthy service. Run it again to rebuild after source changes.

Private-server deployment guide ↗

Trusted networks only

There is no login. Anyone who can reach the server can change content, manage integrations and configure a linked device. Keep it on a trusted LAN or private VPN, without public tunnels or router port forwarding. CSRF protection is not access control.

Keep your data with your server

Back up the entire persistent data directory: source settings in data.json (or your configured filename), device metadata in device.json, and both credentials.json and credentials.key. Both credential files are needed to restore keys; someone who can read both can decrypt them.

Deploy the version you expect

Production Compose uses a published image, which may lag local source changes. Follow the deployment guide to build from source when needed, and check migration notes before replacing an older container.
